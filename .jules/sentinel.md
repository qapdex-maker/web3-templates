## 2025-02-18 - Client-Side DOM-Based XSS in Static HTML Templates
**Vulnerability:** In static interactive Web3 HTML templates using Tailwind CSS, user input retrieved from textarea/input elements is rendered directly via `innerHTML` into the DOM. This allows arbitrary JavaScript execution (Cross-Site Scripting) if an attacker inputs malicious HTML tags or script blocks.
**Learning:** Because the templates are standalone client-side HTML files without any backend server or node packages (no build steps, no external sanitization packages), standard sanitization libraries like DOMPurify or server-side escaping are not readily available or integrated. Developer relies on fast, lightweight vanilla JavaScript templates where `innerHTML` is mistakenly used to build UI components dynamically, creating a high-risk security gap in user input presentation.
**Prevention:** Always implement a dedicated utility function to escape special HTML characters (`&`, `<`, `>`, `"`, `'`) within the script blocks of any template doing client-side rendering. Prior to setting `innerHTML` with dynamic user text, wrap the user input with the escape function, or use safer APIs like `textContent`/`innerText` where raw HTML rendering is not strictly necessary.
